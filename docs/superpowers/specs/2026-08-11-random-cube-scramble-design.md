# 随机魔方状态设计

## 目标

允许用户不经过相机扫描或手动逐格录入，直接从主页生成一个物理合法、可求解的随机 3×3 魔方状态。应用同时展示生成该状态的随机打乱公式和对应魔方六面状态，用户可以继续校验、修改并使用现有求解流程。

## 入口与用户流程

主页在“开始扫描”和“手动录入”旁增加“随机魔方”入口。点击后立即生成一次随机打乱，并进入现有 `CubeEditorPage`：

1. 页面顶部显示“随机打乱”及完整 Singmaster 公式。
2. 魔方展开图显示从复原态执行该公式后的状态。
3. 当前主页配置的 `CubeColorScheme` 继续用于显示贴纸颜色。
4. 用户可以按现有规则修改非中心贴纸、查看合法性并点击“开始求解”。
5. 用户修改贴纸后，随机公式仍保留为初始状态来源说明，不根据后续编辑反向重算。

本次不在编辑页增加“重新随机”按钮；用户需要另一组状态时返回主页再次点击入口，以保持编辑器职责单一。

## 随机生成模型

新增不依赖 Flutter 的 `CubeScrambler` 与不可变结果 `CubeScramble`：

- `CubeScrambler.generate()` 返回 `CubeScramble`。
- `CubeScramble.moves` 保存不可变的 `SolutionMove` 列表。
- `CubeScramble.state` 保存从 `CubeState.solved()` 依次应用 `moves` 得到的状态。
- 默认使用 Dart `Random`，构造函数允许注入随机数源以支持确定性测试。
- 每次先均匀选择 18～25（含两端）的公式长度。
- 每一步从 U、R、F、D、L、B 六个面中选择一个与前一步不同的面。
- 每一步独立选择普通 90°、逆时针 90°或 180°后缀，三种动作概率相同。

生成器通过 `CubeSolver.applyMoves` 复用现有、已经测试的状态变换规则。它不随机排列贴纸，也不直接拼装角块或棱块，因此生成状态天然满足中心固定、每色九枚、块方向和排列奇偶约束。

## 界面与数据传递

`HomePage` 构造并持有一个 `CubeScrambler`，默认使用真实随机源，测试可注入带固定 `Random` 种子的生成器。点击“随机魔方”时同步生成结果，然后构造：

```dart
CubeEditorPage(
  initialState: scramble.state,
  colorScheme: _colorScheme,
  scrambleMoves: scramble.moves,
)
```

`CubeEditorPage` 新增可选、默认为空的 `scrambleMoves` 参数。非空时，在 `CubeNet` 上方显示一个紧凑卡片，标题为“随机打乱”，下方按顺序显示完整公式。公式使用可换行布局，以适配 320dp 窄屏，并提供整体可读的文本语义。

随机公式只属于录入来源元数据，不进入 `CubeState`，也不传给求解器。求解器仍只接收用户当前看到并确认的状态。

## 错误处理与边界

- 长度下限固定为 18、上限固定为 25，不向用户暴露步数配置。
- 相邻动作不能操作同一面，避免 `R R'`、`U U2` 等可直接合并或抵消的序列。
- 允许相邻动作操作同一轴上的不同面，例如 `R L`；这仍是合法且不可直接合并的打乱。
- 空公式不由默认生成器产生；`CubeScramble.fromMoves` 始终从提供的动作列表计算状态，即使测试传入空列表也不会保存不一致的公式和状态。
- 随机状态生成不执行 Kociemba 搜索，因此点击入口没有异步等待或超时错误。

## 测试与验收

- 生成器测试覆盖长度始终位于 18～25、动作格式合法、相邻面不同，以及多组生成结果通过 `CubeValidator`。
- 确定性测试验证 `state == CubeSolver.applyMoves(CubeState.solved(), moves)`，保证公式与状态一致。
- 不可变性测试验证外部无法修改 `moves`。
- Home Widget 测试验证“随机魔方”入口存在，点击后进入编辑页，并把同一次生成结果的状态、公式与当前配色一并传入。
- Editor Widget 测试验证随机公式卡片仅在 `scrambleMoves` 非空时出现，320dp 宽度无溢出，编辑贴纸后公式仍显示。
- 现有扫描、手动录入、求解和播放测试保持通过。
- 发布版本升级为 `1.1.3+5`，更新说明记录随机合法状态与打乱公式入口，并构建、签名和部署 Android Release 到现有更新服务器。
