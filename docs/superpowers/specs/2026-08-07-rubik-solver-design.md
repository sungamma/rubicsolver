# 魔方解法 App 设计说明

## 目标

在 Flutter 中实现一款面向手机的 3×3 魔方复原应用。用户依次拍摄六个面，应用在本地识别颜色、校验魔方状态并提示可能的识别错误；用户可直接编辑贴纸颜色。状态合法后，应用使用成熟的 Herbert Kociemba 两阶段算法生成快速、较短的复原公式，并用可暂停、可逐步前进或后退的播放器演示全过程，同时在屏幕上保留完整解法。

首要平台是 Android，iOS 保持可编译的相机与核心功能。Android 版本复用 `../heat_ex_designer` 的签名身份、GitHub 更新思路和作者信息。

## 已确认约束与自主取舍

- 直接在当前 `master` 分支内联实现，不创建工作树或功能分支。
- 每个可独立验证的阶段完成后主动提交。
- 不依赖云端识别或云端求解，避免网络延迟、服务费用和照片隐私问题。
- 求解使用 pub.dev 的 `cuber 0.4.0`。它是 MIT 许可的纯 Dart Kociemba 两阶段实现，包含预计算表，可在当前 Dart 3.8.1 环境运行。
- 不追求数学意义上的最少步数。最短解搜索在手机上成本过高；两阶段算法优先保证数秒内获得通常不超过 25 步的成熟解法。
- 相机识别采用“受引导的六面采集”，而不是尝试从任意角度的一张照片重建整个魔方。该方式更稳定，也能明确控制各面方向。
- 播放采用实时更新的二维展开图和动作高亮。它比引入不稳定的第三方 3D 引擎更易验证，且能准确显示所有隐藏面的状态变化。

## 用户流程

1. 首页展示“开始扫描”“手动录入”和最近一次状态入口。
2. 扫描页按 `U → R → F → D → L → B` 顺序采集六面。页面展示当前面的中文名称、持握方向、3×3 对齐框和已完成进度。
3. 每次拍照后展示九格识别预览。用户可重拍或接受。
4. 六面完成后，应用用六个中心贴纸作为动态颜色参考，对其余贴纸做感知色差分类。
5. 校验页展示魔方展开图、每种颜色计数、识别置信度及物理合法性结果。
6. 若存在问题，应用高亮低置信度贴纸、颜色超额项及可能需要修改的位置。用户点贴纸即可选择其他颜色；中心贴纸锁定，避免破坏面定义。
7. 合法状态进入求解。求解过程在后台 isolate 中运行，界面显示进度并允许取消或重试。
8. 结果页顶部显示当前魔方展开图，中部显示当前动作及中文说明，底部提供上一步、播放/暂停、下一步、速度和进度控制；完整公式以可换行的动作胶囊常驻屏幕，并可点选跳转。
9. 设置/关于页提供作者信息、隐私说明、算法说明和手动检查更新。

## 架构

应用采用小型、按功能聚合的结构，不引入额外状态管理框架：

```text
lib/
  app/                 应用入口、主题、路由与顶层壳
  cube/                魔方颜色、面、贴纸状态、动作与校验
  scan/                相机控制、照片采样、颜色科学与扫描页面
  editor/              展开图编辑器、错误提示与校验页面
  solver/              cuber 适配、后台求解、解法模型
  playback/            动作应用、播放器状态与结果页面
  update/              GitHub 版本检查、下载/安装与版本比较
  settings/            关于、作者和隐私信息
```

核心业务对象不依赖 Flutter UI，使颜色识别、合法性校验、动作变换和版本比较可以用普通单元测试覆盖。页面只协调这些对象，不复制领域规则。

## 魔方数据模型

- `CubeFace` 固定为 `up/right/front/down/left/back`，序列化顺序为 Kociemba 使用的 `URFDLB`。
- `CubeColor` 表示用户看到的六种实体颜色：白、红、绿、黄、橙、蓝。
- `StickerSample` 保存平均 RGB、亮度、颜色方差、最佳/次佳面标签及置信差。
- `CubeState` 保存 54 个面标签，而不是直接保存实体颜色。每个面的中心贴纸决定实体颜色到 `URFDLB` 的映射，因此不同配色方案也能工作。
- `CubeState.toFacelets()` 产生 `cuber` 所需的 54 字符串。
- 编辑操作不可修改六个中心位置；其他位置修改后立即重新校验。

## 相机识别

### 采集约定

用户始终保持正面中心朝向镜头，并根据页面插图保持“上方”一致。扫描顺序固定，页面会说明下一次如何旋转整个魔方。这样可避免六张照片之间出现镜像或旋转歧义。

### 图像采样

1. 使用 `camera` 拍摄静态照片，使用 `image` 解码并应用 EXIF 方向。
2. 从照片中央裁出正方形区域，与取景框一致。
3. 将区域分成 3×3，每格只采样中心约 36% 的像素，避开黑色缝隙、倒角和反光边缘。
4. 计算去除最亮和最暗异常像素后的平均 RGB，同时记录亮度与方差。
5. 六个中心样本转换到 CIE Lab，成为六类动态参考色。
6. 其余贴纸按 Delta E 76 最小距离分类；最佳与次佳距离之差形成置信度。

识别不会伪装成绝对可靠。低亮度、过曝、高方差、中心颜色过近或分类距离接近时，页面会明确提示重拍或检查对应贴纸。

## 校验与错误建议

校验分三层：

1. **采集质量**：检查每面是否有九个样本、中心参考是否可区分、单格是否过暗/过亮/方差过高。
2. **颜色数量**：每个面标签必须恰好出现九次。出现超额和缺额时，优先建议修改“当前归入超额色、但次佳候选属于缺额色”的低置信度贴纸。
3. **物理合法性**：调用 `Cube.verify()` 检查角块/棱块组合、棱翻转、角扭转和排列奇偶性。错误映射为中文说明；无法精确定位时，高亮全局最低置信度的若干贴纸供用户复查。

只有三层均通过时才允许求解。用户可在展开图上点任意非中心贴纸并选择六种颜色，也可返回重拍某一面。

## 求解

- `CuberSolver` 是第三方包的薄适配层，输入只接受已验证的 54 字符串。
- 求解在 `Isolate.run` 中执行，避免阻塞相机预览和动画。
- 默认最大深度 25，超时 30 秒。多数状态会远早于上限完成。
- 返回值标准化为 `R`、`R'`、`R2` 等动作列表；空列表表示魔方已经复原。
- 超时或求解器异常不会丢失已编辑状态，用户可重试或返回检查。

## 播放

- `MovePlayer` 保存初始状态、动作列表和当前索引。
- 前进时将一个动作应用到当前状态；后退时从初始状态重放到目标索引，避免累计逆操作错误。
- 自动播放默认每步 900 ms，可选 500/900/1400 ms。
- 当前动作显示标准记号和中文说明，例如 `R'` 为“正对右面看，逆时针转动 90°”。
- 展开图高亮正在转动的面，完成后显示“复原完成”。
- 完整公式始终可见，已完成、当前和未完成动作使用不同样式；点击动作可跳到对应步骤。

## 权限与隐私

- Android：相机、网络、安装未知应用；下载使用应用专属目录，不请求宽泛的存储管理权限。
- iOS：在 `Info.plist` 中提供中文相机用途说明。
- 所有照片只在设备本地解码，接受或重拍后即可释放；不上传，也不写入相册。
- 相机不可用或用户拒绝权限时，仍可进入手动录入流程。

## 测试与验收

- 单元测试覆盖面序列化、颜色计数、合法/非法状态、错误建议、Lab 色差、动作应用、解法解析和版本比较。
- 求解集成测试至少覆盖：已复原魔方、单动作打乱、多动作打乱，并验证把解法应用后确实复原。
- Widget 测试覆盖：首页入口、编辑贴纸、非法状态禁用求解、播放器控制和作者信息。
- 交付前依次运行 `dart format --set-exit-if-changed .`、`flutter analyze`、`flutter test` 和 `flutter build apk --debug`。
- Android 真机验收关注相机方向、裁剪框对应关系、暗光/反光提示、安装更新跳转和签名构建。

## 非目标

- 本阶段不支持 2×2、4×4 或更高阶魔方。
- 不做任意背景下的一张图多面识别。
- 不提供账号、云同步、排行榜或计时竞速功能。
- 不承诺数学最短解，也不加入需要联网付费的视觉模型。
